# NAVIS 이상탐지 코드 (v2.5, 최종)

## 목표
항적만 보고 **바다 위에서** 사고로 이어질 수 있는 움직임(신호 단절, 장시간 정지, 표류)을 **놓치지 않되**,
담당자가 **매일 확인할 수 있는 양**(하루 '경보' 20건 이하)으로, **왜 경보인지 사유를 붙여** 알린다.

최종 결과물 (역할분담표의 '넘겨줄 것')
1. 선박·시간별 이상점수: `scores_deliverable.parquet`
2. 경보 선박 목록: `alarm_vessels.csv` (+ 사건 목록 `alarm_events.csv`, 시간별 기록 `alarm_rows.csv`)
3. 임계값 기준: `임계값_기준.md` (사람용 설명서), `final_thresholds.json` (기계용)

## 경로 설정 (절대경로 없음)
모든 단계는 `navis_paths.py` 한 곳에서 경로를 가져온다. 우선순위는 **환경 변수 → `navis_paths.json` → 레포 기본 구조**.

레포를 아래 구조로 두면 아무것도 설정하지 않아도 된다 (ROOT = 레포 루트).

```
ROOT/
  NAVIS_anomaly_final/           ← 이 코드
  NAVIS_features/                ← navis_features.py 결과 (features_vpass_*.parquet, thresholds.json)
  NAVIS_classifier/navis_anomaly/ ← 분류 담당 패키지 (classifier.py 등)
  data/vpass_1월_6월 데이터/       ← 학습 원본 CSV
  data/테스트셋/                   ← 테스트 원본 CSV
  data/제출샘플.xlsx
  out/NAVIS_anomaly/             ← 이상탐지 결과
```

데이터가 다른 곳에 있으면 `navis_paths.example.json`을 `navis_paths.json`으로 복사해 그 항목만 고친다
(상대경로는 레포 루트 기준, 이 파일은 `.gitignore`로 깃에 올리지 않음).
지금 경로 확인: `python navis_paths.py`

## 분류 모델과 연결 (import 해서 함수로 호출)
분류 담당(혜승님) 패키지를 결과 파일 없이 **import 해서 함수로** 부른다. 연결 코드는 `cls_bridge.py` 하나다.

| 이상탐지 단계 | 부르는 함수 | 쓰는 곳 |
| --- | --- | --- |
| 5단계 `step5_mismatch.py` | `cls_bridge.train_vessel_oof()` | 학습 선박별 업종 확률(선박 단위 교차검증 OOF) → 업종 불일치 지표 |
| 9단계 `step9_testB.py` | `cls_bridge.predict_vessels(테스트 원본)` | 학습 데이터에 없는 선박의 업종 |

- `cls_bridge` 가 부르는 분류 패키지 함수: `raw_sources.iter_raw_sources / read_source`, `hourly_raw.build_hourly`,
  `classifier.vessel_features`, `classifier.VesselTypeClassifier().fit / .predict` (공개 함수만 사용)
- 분류 담당이 `classifier.py` 를 고도화하면 이상탐지 쪽은 코드 수정 없이 새 모델을 쓴다 (5단계부터 다시 실행)
- 분류 패키지 위치: `navis_paths.json` 의 `cls_repo` (기본: 레포/`NAVIS_classifier`, 그 안에 `navis_anomaly/classifier.py`)
- 학습 원본 → 시간별 통계(분류 전처리 중간값)는 결과 폴더 `cache/` 에 저장해 두 번째 실행부터 빠르다.
  분류 확률 자체는 저장하지 않고 매번 함수로 계산한다. 원본이나 분류 전처리 코드가 바뀌면 자동으로 다시 만든다 (끄기: `NAVIS_CLS_CACHE=0`)
- 연결 점검: `python cls_bridge.py` → 선박 단위 교차검증 정확도(= micro-F1)와 혼동행렬
- 분류 패키지를 찾지 못하면 5단계는 불일치 지표 0, 9단계는 점수 기준 업종 추정으로 진행하고 경고를 출력한다

## 한계 (보고서에 그대로 적을 내용)
- 정답 라벨이 없어 인위적 이상과 사례 검토로만 검증했다. 인위적 이상의 모양(표류 속도, 정지 시간)이 결과에 영향을 준다.
- 모항 근처(규칙 거리 이내)의 신호 단절·정지·점수 이상은 경보하지 않는다. 항구 귀항·정박과 구분할 수 없고, 사고 예방 대상이 바다 위이기 때문이다.
- 바다 위 신호 단절과 장시간 정지는 이 데이터에서 실제로 흔하다(모항 2km 밖 단절을 겪은 선박 38%). V-Pass 통신 범위와 정상 조업(양망 대기 등) 때문으로 보이며, 그래서 규칙 기준을 하루 경보 예산에 맞춰 고른다.
- 4차 보고서의 '모항을 못 찾아서 단절이 과다하다'는 진단은 v2.3에서 확인되지 않았다 (새 방식으로만 찾은 모항 196곳, 단절 빈도 74.3 → 74.0건/일).
- 3시간 정지와 표류는 정상 조업과 비슷해서 탐지율이 낮다.
